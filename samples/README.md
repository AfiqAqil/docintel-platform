# Synthetic sample documents

All documents in `out/` are fictional (architecture assumption 8): invented people, an
invented insurer, and addresses and phone numbers drawn from ranges reserved for fiction
(`example.com`, the UK's `07700 900xxx` range). Generated by `generate.py`.

Re-running it produces byte-identical output for ten of the eleven files, so a diff under
`out/` means the generator changed rather than that it was run again.

`corrupt_encrypted.pdf` is the exception, and deliberately so. It is encrypted with a
password generated at run time and never returned, logged or stored, so no copy of it exists
once generation finishes. Its bytes therefore differ on every run. Keeping it byte-identical
would require the password to be reproducible, which is the same as keeping it, and a
password committed beside the file it locks is not worth the determinism. The file is
unreadable to the platform either way: `rules/parse.py` tries only the empty password.

Run with:

```
python samples/generate.py --out samples/out
```

## Samples

| File | Format | Exercises |
|---|---|---|
| `claim_form_complete.pdf` | PDF, real text | Happy path. Every `ClaimFormExtraction.REQUIRED_FIELDS` value present and valid. Outcome `COMPLETE` |
| `claim_form_incomplete.pdf` | PDF, real text | Claim reference and claimed amount omitted entirely. Outcome `INCOMPLETE` |
| `claim_form_bad_dates.pdf` | PDF, real text | Date of incident after date filed, the one cross-field rule in `validate.py`. Triggers a validation error and the retry cycle |
| `invoice_repair.pdf` | PDF, real text | Invoice extraction. 4 line items summing exactly to the stated total, one amount with a thousands separator |
| `policy_document.docx` | DOCX | `python-docx` reading path and the generic extractor. Paragraphs plus a coverage table, since table cell text is read separately from paragraphs |
| `customer_correspondence.docx` | DOCX | Generic extractor on prose. A complaint letter about a claim |
| `identity_card.png` | PNG | Image path, no text layer. Snippet verification is skipped. Card layout with fields rendered as pixels |
| `damage_photo.jpg` | JPG | Supporting evidence. A standalone synthetic scene, not a document scan |
| `claim_form_scanned.pdf` | PDF, image only | `pypdfium2` render path. The complete claim form rendered to an image and embedded as a full page PDF with no text layer |
| `restaurant_menu.pdf` | PDF, real text | Out of scope document type. Classification routes to `UNSUPPORTED` |
| `corrupt_encrypted.pdf` | PDF, encrypted | Unreadable, terminal failure, status `FAILED` |

## External documents

`external/` holds six documents this repository did not generate. They were produced by a
separate tool from a plain description ("a completed claim form", "a repair invoice with
four line items"), with their own layout, their own people and their own insurer, and with
no knowledge of this platform's prompts or rules. Everything in them is fictional, and the
identity card is marked as a specimen.

They exist because a platform tested only against documents shaped by its own generator is
testing its assumptions. These found two real defects that the eleven samples above never
could, both recorded in [`docs/BUILD_LOG.md`](../docs/BUILD_LOG.md).

| File | Format | Result | Why |
|---|---|---|---|
| `01_completed_claim_form.pdf` | PDF | `COMPLETE` | |
| `02_blank_claim_reference_and_amount.pdf` | PDF | `INCOMPLETE` | The two blank fields are printed as underscores, and are reported as missing rather than extracted as a value |
| `03_repair_invoice.pdf` | PDF | `COMPLETE` | Line items are a real table, with the header row far from the cells |
| `04_policy_schedule.docx` | DOCX | `COMPLETE` | Coverage table inside a DOCX |
| `05_delayed_claim_complaint.docx` | DOCX | `COMPLETE` | Prose correspondence |
| `06_eldoria_national_identity_card_specimen.png` | PNG | `INCOMPLETE` | Its number, `ELD-260921-74`, does not match this platform's own identity number convention, one letter and eight digits. That is the format rule working, on a document that was never told the rule |

Reports from a real model are in `external/reports/`. To reproduce:

```
cd worker
LLM_PROVIDER=openai LLM_MODEL_ID=gpt-4o-mini python run_local.py \
  --samples ../samples/external --out ../samples/external/reports
```
